# Jellyfin Media Server Pack

Public-safe starter context for a fictional self-hosted Jellyfin media server.

This starter pack is a curated local example, not a marketplace listing and not an endorsement by the Jellyfin Project. Third-party marks are used only as identifiers.

The records are synthetic, public-safe notes for exercising Contextarr validation, review, render, compose, and export flows. The pack contains no credentials, no private data, no install hooks, and no executable commands.

## Why this pack exists

This pack shows how a self-hosted media server can document library, storage, client, and transcoding decisions without exposing host paths, user identities, credentials, or copyrighted media details.

## What an AI can safely know

An AI can know synthetic library roles, client classes, storage support boundaries, backup posture, and transcoding decision criteria.

## What must never be exported

Never export credentials, invite links, public endpoints, real usernames, media filenames, host paths, device IDs, hardware serials, network addresses, logs, or instructions for bypassing access controls.

## Best export target

Use Markdown or Codex exports for operational review. Use JSON records for local validation of media-server context boundaries.

## Demo question to ask

What should be checked before changing transcoding settings?

## Proof path

Review `records/transcoding-policy.md`, `records/storage-map.md`, `raw/transcoding-policy.md`, and `raw/storage-map.md` to confirm resource and storage boundaries are specific but public-safe.
