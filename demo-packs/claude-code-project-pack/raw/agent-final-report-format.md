# Agent Final Report Format Source Note

Maintainer note from a fictional coding-agent project handoff.

The preferred final report is short and evidence-led. It starts with what changed, then lists validation performed, then calls out known residual risk. Long implementation essays are discouraged unless the change crosses module boundaries.

| Report part | Expected content |
| --- | --- |
| Summary | One or two sentences describing the delivered change. |
| Validation | Exact local checks or a clear statement that checks were not run. |
| Follow-up | Only concrete next actions, not speculative roadmap items. |

The report should not include hidden chain-of-thought, copied private paths, or claims that a deploy or release happened.
