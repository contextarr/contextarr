# GitHub Workflow Pack

Public-safe starter context for fictional GitHub repository workflows.

This starter pack is a curated local example, not a marketplace listing and not an endorsement by GitHub. Third-party marks are used only as identifiers.

The records are synthetic, public-safe notes for exercising Contextarr validation, review, render, compose, and export flows. The pack contains no credentials, no private data, no install hooks, and no executable commands.

## Why this pack exists

GitHub Workflow Pack demonstrates how repository process notes can be shaped into public-safe assistant context for pull request review, release readiness, issue triage, and security alert handling.

## What an AI can safely know

An AI can safely know the fictional repository's review gates, release signals, branch policy, issue labels, and evidence expectations. It may distinguish review readiness from release readiness using only the approved records.

## What must never be exported

Never export real repository URLs, organization names, issue numbers, contributor emails, tokens, private security reports, undisclosed vulnerability details, branch protection screenshots, or executable automation instructions.

## Best export target

Use the Codex target for a coding-agent workflow brief. Use Markdown when a maintainer needs a release-review checklist.

## Demo question to ask

Is this PR ready to release, or only ready to review?

## Proof path

Start with the pull request template, then compare release process, branch policy, actions workflows, and code review rules. The expected proof is a source-backed readiness classification with boundaries and missing evidence called out.
