# VS Code Setup Pack

Public-safe starter context for a fictional VS Code developer setup.

This starter pack is a curated local example, not a marketplace listing and not an endorsement by Microsoft. Third-party marks are used only as identifiers.

The records are synthetic, public-safe notes for exercising Contextarr validation, review, render, compose, and export flows. The pack contains no credentials, no private data, no install hooks, and no executable commands.

## Why this pack exists

VS Code Setup Pack demonstrates how editor preferences, extension groupings, task conventions, language tooling, and debugging notes can be exported as safe context for coding agents without dumping private workspace settings.

## What an AI can safely know

An AI can safely know the fictional editor profile roles, extension categories, task labels, debug scenario names, accessibility preferences, and known editor friction. It may recommend which reviewed record is relevant to a coding-agent task.

## What must never be exported

Never export real absolute paths, SSH hosts, tokens, synced settings dumps, private extension identifiers, workspace names, environment files, launch arguments with secrets, or executable editor-change instructions.

## Best export target

Use the Codex or AGENTS.md target for coding-agent setup context. Use Markdown when a human wants a public-safe overview of the editor profile.

## Demo question to ask

Which extension/debug setup is relevant for a coding-agent task?

## Proof path

Start with extension groups, then compare debugging notes, language tooling, task conventions, and workspace settings. The expected proof is a short mapping from task type to reviewed setup category, with non-exportable settings excluded.
