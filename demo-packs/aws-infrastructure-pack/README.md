# AWS Infrastructure Pack

Public-safe starter context for fictional AWS infrastructure documentation.

This starter pack is a curated local example, not a marketplace listing and not an endorsement by Amazon Web Services. Third-party marks are used only as identifiers.

The records are synthetic, public-safe notes for exercising Contextarr validation, review, render, compose, and export flows. The pack contains no credentials, no private data, no install hooks, and no executable commands.

## Why this pack exists

AWS Infrastructure Pack demonstrates how a team can turn cloud architecture notes, backup expectations, cost review signals, and environment boundaries into reviewed context that is useful to assistants without exposing live infrastructure.

## What an AI can safely know

An AI can safely know the fictional environment roles, approval checkpoints, resilience intent, cost-review cadence, and escalation labels. It may compare records and identify which reviewed note should be consulted before a policy discussion.

## What must never be exported

Never export real account identifiers, ARNs, resource names, hostnames, private addresses, credentials, provider-console steps, incident logs, shell commands, executable deployment instructions, or customer data.

## Best export target

Use the Codex or Claude target for an infrastructure review brief. Use Markdown when a human reviewer needs a compact public-safe summary.

## Demo question to ask

What is the safe review path before changing backup or cost policy?

## Proof path

Start with the environment map, then compare backup and recovery, cost controls, IAM boundaries, and deployment patterns. The expected proof is a source-backed answer that names the review checkpoints without exposing private identifiers or operational instructions.
